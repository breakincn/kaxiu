# 预约主链重构收尾说明

## 目的

在前一轮完成预约主链重构后，运行代码里仍残留两类旧语义：

1. 商户侧仍暴露 `appointment_max_wait_minutes` 配置，容易让人误以为预约仍按“可承诺等待上限”设计。
2. 用户端、商户端和部分接口仍使用 `wait` 命名，例如 `predicted_wait_minutes`、`current_estimated_wait_minutes`，会继续把预约延迟理解成“排队等待”。

本轮目标是把这些尾项彻底收掉，让运行代码的产品语义与《预约新规与预约资源锁定补偿一体化方案》保持一致。

## 本轮完成项

- 商户预约设置页不再展示“预约最大等待”输入项。
- 商户服务开关页不再携带 `appointment_max_wait_minutes`。
- `UpdateCurrentMerchantServices` 不再接受 `appointment_max_wait_minutes` 请求参数。
- `Merchant.AppointmentMaxWaitMinutes` 保留数据库字段，仅作为历史兼容列存在，运行时 JSON 已隐藏，并标记为“已弃用”。

## 当前语义

本轮完成后，预约运行语义已经收敛为：

- 预约不再有独立排队概念，也不再有“预约最大等待”配置。
- 预约成功表示资源锁定。
- 预约到店后正常进入执行链，不再以 `appointment_waiting` 作为正常主路径。
- 如果原预约客服仍未释放，系统记录的是“预约延迟/履约异常”，而不是“预约排队”。

## 历史兼容边界

以下内容仍保留，但仅作为存储兼容，不再作为运行时产品能力：

- `merchants.appointment_max_wait_minutes`
- `appointments.predicted_wait_minutes`

说明：

- 这两个数据库列没有删除，避免直接触发迁移和历史数据兼容风险。
- 运行时 API、前端页面、商户配置入口已经不再使用旧语义。
