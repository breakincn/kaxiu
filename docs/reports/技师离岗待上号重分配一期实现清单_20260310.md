# 技师离岗待上号重分配一期实现清单

- 文档日期：2026-03-10
- 对应主题：多客服叫号模式下，技师离岗前的待上号单自动重分配

## 1. 本期实现目标

本期只解决一个最小问题：

- 在多客服叫号模式下，若某个技师当前挂有 1 个 `start_pending` 待上号单，且该技师准备暂停叫号或下班，系统提供一个安全、窄口径的“自动转交给其他空闲客服”能力

本期明确不做：

- 手工指定改派给某个客服
- 立即跳过
- 批量处理全店异常待上号单
- 对 `serving / delay_pending` 会话做改派

## 2. 已实现功能

### 2.1 后端新增自动重分配接口

新增接口：

- `POST /merchant/queue/sessions/:id/reassign-current-pending`

能力说明：

- 仅支持当前处于 `start_pending`、尚未 `start_confirmed` 的待上号单
- 仅支持多客服叫号模式
- 自动选择“其他空闲、已签到、未暂停、无活跃会话”的客服接手
- 重分配成功后：
  - 更新 `service_sessions.technician_id`
  - 将原客服从 `busy` 释放为 `idle / paused`
  - 将新客服从 `idle` 置为 `busy`

权限说明：

- 商户老板账号可操作任意待上号单
- 运营类工作人员可操作任意待上号单
- 专业客服仅允许转交自己当前的待上号单

### 2.2 商户首页“今日核销记录”增加“客服不可服务”轻提示

后端 `usages` / `pending-list` 返回新增字段：

- `technician_name`
- `technician_available`
- `technician_unavailable_reason`

当前会在以下情况下显示不可服务提示：

- 客服已暂停叫号
- 客服已暂停服务
- 客服已下班

前端在商户首页“扫码核销”Tab 的“今日核销记录”中展示：

- 当前客服姓名
- 不可服务原因
- 满足条件时显示“重新分配”按钮

### 2.3 专业客服离岗前自助转交

在专业客服端：

- 点击“暂停叫号”前
- 点击“下班签到”前

若系统发现当前账号名下有 1 个 `start_pending` 待上号单，会弹出确认框：

- 是否先尝试转交给其他空闲客服

若转交成功，再继续执行暂停/下班动作。

## 4. 安全边界与正确性设计

本期实现刻意收窄了范围，保证不影响现有主链：

- 只处理 1 个当前待上号单，不碰其他已分配单
- 不处理已开始服务的单
- 不改变队列号顺序
- 不做全店批量调度
- 若当前没有可接手的空闲客服，则直接失败，保留原状态，不做隐式跳过
- 整个重分配过程在事务内完成，避免出现“单子换人了，但两边考勤没同步”的中间态

## 5. 本期收益

- 降低多客服叫号模式下，技师离岗导致待上号单被动超时的概率
- 让商户/运营可以直接在商户首页“今日核销记录”里处理“当前客服不可服务”的待上号单
- 让专业客服在离岗前自助转交自己当前单，减少现场口头协调
