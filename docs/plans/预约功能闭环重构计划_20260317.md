# 预约功能闭环重构计划

日期：2026-03-17

## 目标
本次重构把原来的“独立预约状态切换”收敛为正式业务闭环：

`预约确认 -> 占产能 -> 到店核销(arrived) -> ServiceSession -> completed/no_show`

重点覆盖客服模式下的三类真实门店场景：

1. 预约一旦确认，即占用指定客服的未来产能。
2. 到店后不再手工“完成预约”，而是进入正式服务会话。
3. 当前序现场单压到预约时，预约客户进入“预约优先等待”，且优先级高于普通现场单。

## 本次实施范围

### 1. 数据模型与迁移
- 在 `merchants` 新增预约保护参数：
  - `appointment_reserve_buffer_minutes`
  - `appointment_grace_window_minutes`
  - `appointment_max_wait_minutes`
  - `appointment_prediction_buffer_minutes`
- 在 `appointments` 新增：
  - `confirmed_at`
  - `arrived_at`
  - `completed_at`
  - `no_show_at`
  - `service_session_id`
  - `usage_id`
  - `predicted_wait_minutes`
  - `resolution_note`
- 在 `service_sessions` 新增：
  - `occupies_next_appointment`
  - `next_appointment_id`
  - `predicted_appointment_delay_minutes`
  - `predicted_ready_at`
- 预约状态统一为：
  - `pending`
  - `confirmed`
  - `arrived`
  - `completed`
  - `canceled`
  - `failed`
  - `no_show`
- 历史 `finished` 只做兼容读取，不再作为新写入状态。

### 2. 预约占产能与候选客服规则
- 新增统一预约策略实现，后端集中计算：
  - 预约保留区间
  - 候选客服可用性
  - 预计等待分钟数
  - `safe / conditional / unavailable`
- 核心规则：
  - 预约确认后即保护指定客服未来时段
  - 自动派单、用户主动选客服、预约自动分配共用同一套判断
  - `predicted_reserved_wait > appointment_max_wait_minutes` 时不可派
- 默认缓冲：
  - 收尾缓冲 3 分钟
  - 风险缓冲取商户配置，默认 5 分钟

### 3. 客服模式下的“预约保护 + 替代优先”
- 现场客分配给预约客服前，先计算：
  - `delay_reserved`
  - `delay_walkin_alt`
- 固定成本函数：
  - `reserved_weight = 2.5`
  - `walkin_weight = 1.0`
- 决策顺序：
  - 先满足预约等待上限
  - 再比较替代方案成本
  - 只有当占用预约客服成本不更高时，才允许“压预约派单”
- 一旦压预约派单，当前服务会话会显式写入风险标记，供后续调度和前端展示使用。

### 4. 到店核销与服务闭环
- 预约到店继续走现有核销入口，不再走独立“完成预约”入口。
- 命中预约核销后：
  - 预约状态更新为 `arrived`
  - 回写 `usage_id`
  - 回写 `service_session_id`
- 两种落地路径：
  - 客服可立即接待：直接进入正常 `ServiceSession`
  - 客服仍忙：进入 `appointment_waiting`
- `appointment_waiting` 语义：
  - 客户已到店
  - 默认绑定原预约客服
  - 优先级高于普通现场单
  - 后续普通现场单不得再插队

### 5. 调度器与状态推进
- 服务调度器新增 `appointment_waiting` 推进逻辑：
  - 优先等待原客服释放
  - 释放后优先推进该预约等待会话
  - 需要房间时继续进入选房/待开始链路
- 预约调度器新增：
  - 未选客服预约的保护式自动分配
  - 超过宽限仍未到店的 `confirmed -> no_show`

### 6. 完成与兼容
- `PUT /merchant/appointments/:id/finish` 保留但废弃，仅返回明确提示。
- 服务完成时，若会话来源是预约，则自动把预约更新为 `completed`。
- 未正式起单但被系统完成的预约来源会话，也会同步把预约收敛到 `completed`。

### 7. 商户端与用户端界面
- 用户预约页：
  - 展示客服级候选
  - 支持 `safe / conditional` 风险展示
  - `conditional` 展示预计等待分钟数
- 商户服务设置页：
  - 可配置四个预约保护参数
- 商户预约页：
  - 支持商户账号直接查看预约
  - 新增 `arrived / completed / no_show / failed` 展示
  - 去掉旧的“完成服务(扣次)”按钮
  - 新增风险提示与处理备注展示
  - 新增三个冲突处理入口：
    - 继续等待原客服
    - 改派其他客服
    - 改签/补偿备注
- 核销成功提示：
  - 若命中预约，会提示已到店闭环或预约等待信息

## API 与行为变化

### 新增或调整
- `GET /merchant/merchants/:id/available-slots`
  - 增加客服候选明细与风险字段
- `POST /user/appointments`
  - 创建时做事务化预约保护校验
- `GET /user/cards/:id/appointment`
  - 返回 `status`、`service_session_id`、`predicted_wait_minutes`、`can_arrive_now`
- `POST /merchant/verify/prepare`
- `POST /merchant/verify/commit`
  - 命中预约时返回：
    - `appointment_status`
    - `predicted_wait_minutes`
    - `session_wait_state`
    - `bound_technician_id`
- `PUT /merchant/appointments/:id/resolution`
  - 新增改签/补偿/人工处理备注接口

### 废弃但保留兼容
- `PUT /merchant/appointments/:id/finish`
  - 不再推进预约完成
  - 仅提示“预约完成已改为随核销/服务会话自动闭环”

## 关键业务规则

### 预约保留区间
- `hold_start = appointment_time - appointment_reserve_buffer_minutes`
- `hold_end = appointment_time + project_duration + appointment_grace_window_minutes`

### 现场派单的预约保护
- `predicted_finish_at = walk_in_start + duration + 3min + prediction_buffer`
- `predicted_reserved_wait = max(0, predicted_finish_at - next_appointment_time)`
- 若 `predicted_reserved_wait > appointment_max_wait_minutes`，则该客服不可派

### 替代优先
- 若存在其他客服方案，比较：
  - `cost_reserved = delay_reserved * 2.5`
  - `cost_alt = delay_walkin_alt * 1.0`
- 仅当 `cost_reserved <= cost_alt` 时允许占用预约客服
