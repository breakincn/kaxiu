# 改签时间窗口与预约保护规则实施计划

## 已实施规则

本次实施把“普通预约只支持明天”和“改签资格判断”拆成了两条独立链路：

- 普通用户创建预约：仍然只支持预约明天。
- 改签：走专用资格判断与专用时段查询，不再直接复用普通预约时段接口。

统一时区：

- 所有改签资格判断按 `Asia/Shanghai` 计算。

改签资格规则：

1. 预约日期是今天：
- 允许改签。
- 只能改签到明天。

2. 预约日期是昨天：
- 先按“今天同一时刻锚点”计算剩余分钟数。
- 默认商户阈值：
  - `180` 分钟：昨天预约可改签到今天或明天。
  - `90` 分钟：昨天预约仅可改签到明天。
- 规则：
  - `> 180` 分钟：可改签到今天或明天。
  - `> 90 && <= 180` 分钟：只能改签到明天。
  - `<= 90` 分钟：禁止改签。
- 如果该预约已经发生过“预约保护拒派审计”，则昨天预约在今天禁止改签。

3. 预约日期早于昨天：
- 禁止改签。

4. 预约日期晚于今天：
- 当前产品边界下，仍只允许改签到明天。

## 商户新增配置

商户预约设置页新增了两个参数：

- `appointment_reschedule_same_or_next_day_threshold_minutes`
  - 中文含义：昨天预约可改签到今天或明天的剩余分钟阈值
  - 默认值：`180`

- `appointment_reschedule_next_day_only_threshold_minutes`
  - 中文含义：昨天预约仅可改签到明天的剩余分钟阈值
  - 默认值：`90`

这两个参数只影响“昨天预约在今天的补救改签”。

## 正式审计表

新增表：`appointment_protection_blocks`

表注释：

- `预约保护拒派审计表`

字段与中文注释：

- `id`
  - `主键ID`
- `merchant_id`
  - `商户ID`
- `appointment_id`
  - `被保护的预约ID`
- `technician_id`
  - `被保护预约绑定的客服ID`
- `walk_in_service_session_id`
  - `被拒绝分配的现场服务会话ID`
- `blocked_reason`
  - `拒派原因说明`
- `predicted_reserved_wait_minutes`
  - `若继续派单将导致预约等待的预计分钟数`
- `alternative_wait_minutes`
  - `改派其他客服的预计等待分钟数`
- `decision_mode`
  - `拒派决策模式（max_wait_protection/alternative_preferred）`
- `blocked_at`
  - `拒派发生时间`
- `created_at`
  - `创建时间`

主要索引：

- `merchant_id`
- `appointment_id`
- `technician_id`
- `walk_in_service_session_id`
- `blocked_at`

写入时机：

- 仅当客服模式现场派单最终因为保护后续预约而实际拒绝把现场客派给该客服时写入。
- 只展示候选、不形成真实拒派时不写入。

## 后端实现

新增统一资格函数：

- `computeAppointmentRescheduleEligibility(...)`

返回字段：

- `allowed`
- `reason`
- `rule_mode`
- `allowed_dates`
- `default_date`
- `minutes_until_anchor`
- `protection_consumed`

新增专用接口：

- `GET /user/appointments/:id/reschedule-eligibility`
- `GET /merchant/appointments/:id/reschedule-eligibility`
- `GET /user/appointments/:id/reschedule-slots`
- `GET /merchant/appointments/:id/reschedule-slots`

实现约束：

- 改签提议创建时做一次资格校验。
- 最终执行改签时再做一次资格校验。
- 前端不能绕过后端规则直接改签到非法日期。

## 前端实现

用户端和商户端改签弹窗现在统一改为：

1. 打开弹窗先请求 `reschedule-eligibility`
2. 使用服务端返回的 `default_date`
3. 使用服务端返回的 `allowed_dates` 约束日期可选范围
4. 再按选中日期请求 `reschedule-slots`

弹窗行为：

- `forbidden`
  - 直接显示不可改签原因
  - 不允许继续选日期和时段

- `tomorrow_only`
  - 只能改签到明天

- `today_or_tomorrow`
  - 只能选择今天或明天
  - 如果今天没有可改签时段，会提示“今天已无可改签时段，可改签到明天”

同时修复了旧问题：

- 不再默认取原预约日期作为改签日期
- 不能再选今天之前的日期
- 不再因为复用普通预约接口而出现“提示只支持明天，但日期还能选过去时间”的错误交互

## 关键测试场景

- 今天预约：只能改签到明天。
- 昨天预约且距离今天锚点时间大于 180 分钟：可改签到今天或明天。
- 昨天预约且剩余分钟大于 90 且不大于 180：只能改签到明天。
- 昨天预约且剩余分钟不大于 90：禁止改签。
- 昨天预约即使时间窗口允许，但若已经写入 `appointment_protection_blocks`：禁止改签。
- 允许改到今天但今天无时段时：前端提示今天无可改签时段，可改签到明天。
- 用户端和商户端对同一预约返回一致的资格结果。
