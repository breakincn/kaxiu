# 改签时间窗口与预约保护规则实施计划

**更新日期**：2026-04-09  
**执行者**：Codex

## 当前生效口径

本次修订明确收敛“用户主动改签 / 商户保护性改签”的目标日期范围：

- 改签只允许发生在 `原预约服务日` 内。
- 不允许跨日改签。
- 不允许跨预约天改签。
- 普通新预约仍按独立规则开放，不与改签日期范围混用。

统一时区：

- 所有改签资格判断按 `Asia/Shanghai` 计算。

## 改签资格规则

1. 预约日期早于今天：
- 禁止改签。
- 原因：已过原预约日，不再允许补救性跨日改签。

2. 预约日期是今天或未来某天：
- 仅允许改签到该预约原本所属的服务日。
- 目标时段仍需满足：
  - 商户营业时间
  - 已发布可预约排班
  - 项目时长与硬冲突约束
  - 现有预约保护与排布校验

3. 改签截止时间：
- 默认截止到 `预约服务开始前 60 分钟`。
- 达到或超过截止时间后，禁止改签。
- 返回原因：
  - `距预约开始不足 60 分钟，当前不可改签`

4. 商户保护性改签：
- 仍只允许修复到 `原服务日` 内。
- 同样受“改签截止时间”约束。
- 若无高质量修复候选，则改走取消/补偿分流。

## 商户新增配置

商户预约设置页保留一个改签参数：

- `appointment_reschedule_deadline_minutes_before_start`
  - 中文含义：预约改签截止时间（距服务开始前分钟数）
  - 默认值：`60`
  - 生效范围：用户主动改签、商户保护性改签

旧字段：

- `appointment_reschedule_same_or_next_day_threshold_minutes`
- `appointment_reschedule_next_day_only_threshold_minutes`

以上字段已停止参与改签资格判断，不再作为前端设置项展示。

## 正式审计表

新增表：`appointment_protection_blocks`

表注释：

- `预约保护拒派审计表`

字段与中文注释：

- `id`
  - `主键ID`
- `merchant_id`
  - `商户ID`
- `appointment_id`
  - `被保护的预约ID`
- `technician_id`
  - `被保护预约绑定的客服ID`
- `walk_in_service_session_id`
  - `被拒绝分配的现场服务会话ID`
- `blocked_reason`
  - `拒派原因说明`
- `predicted_reserved_wait_minutes`
  - `若继续派单将导致预约等待的预计分钟数`
- `alternative_wait_minutes`
  - `改派其他客服的预计等待分钟数`
- `decision_mode`
  - `拒派决策模式（max_wait_protection/alternative_preferred）`
- `blocked_at`
  - `拒派发生时间`
- `created_at`
  - `创建时间`

主要索引：

- `merchant_id`
- `appointment_id`
- `technician_id`
- `walk_in_service_session_id`
- `blocked_at`

写入时机：

- 仅当客服模式现场派单最终因为保护后续预约而实际拒绝把现场客派给该客服时写入。
- 只展示候选、不形成真实拒派时不写入。

## 后端实现

新增统一资格函数：

- `computeAppointmentRescheduleEligibility(...)`

返回字段：

- `allowed`
- `reason`
- `rule_mode`
- `allowed_dates`
- `default_date`
- `minutes_until_anchor`
- `protection_consumed`

新增专用接口：

- `GET /user/appointments/:id/reschedule-eligibility`
- `GET /merchant/appointments/:id/reschedule-eligibility`
- `GET /user/appointments/:id/reschedule-slots`
- `GET /merchant/appointments/:id/reschedule-slots`

实现约束：

- 改签提议创建时做一次资格校验。
- 最终执行改签时再做一次资格校验。
- 前端不能绕过后端规则直接改签到非法日期。
- 后端统一只放行 `allowed_dates = [原预约服务日]`。

## 前端实现

用户端和商户端改签弹窗现在统一改为：

1. 打开弹窗先请求 `reschedule-eligibility`
2. 使用服务端返回的 `default_date`
3. 使用服务端返回的 `allowed_dates` 约束日期可选范围
4. 再按选中日期请求 `reschedule-slots`

弹窗行为：

- `forbidden`
  - 直接显示不可改签原因
  - 不允许继续选日期和时段

- `same_day_only`
  - 只能选择原预约服务日
  - 如果原预约日内已无候选时段，会提示“原预约日内暂无可改签时段”

同时修复了旧问题：

- 不再默认取原预约日期作为改签日期
- 不能再选原预约日之外的日期
- 不再出现“申请改签却实际跳去查询明天排班”的错误交互

## 关键测试场景

- 今天预约且未到截止时间：只能改签到今天剩余营业时段。
- 今天预约且距离开始不足 60 分钟：禁止改签。
- 明天预约：今天可以提前改签，但目标仍只能落在明天营业时段。
- 已过原预约日：禁止改签。
- 商户保护性改签仅允许原服务日修复，且无候选时直接走取消分流。
- 用户端和商户端对同一预约返回一致的资格结果。
