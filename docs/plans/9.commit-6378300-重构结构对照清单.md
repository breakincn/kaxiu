# commit 6378300 重构结构对照清单

本文档用于对照 `commit 6378300` 的重构落地结果，给出“入口覆盖矩阵 / 结构变化清单 / 风险与修复项”，用于验收与后续迭代。

## 1. 目标与范围

- **目标**：彻底补齐 P1（模式防串用校验）在核心入口与状态推进链路中的缺口，并将 legacy 空 `session_mode` 兼容收敛到统一函数。
- **范围文件**：
  - `backend/models/session_mode.go`
  - `backend/handlers/service_session.go`
  - `backend/handlers/service_session_user.go`
  - `backend/handlers/queue_status.go`
  - `backend/handlers/technician_attendance.go`
  - `backend/scheduler/service_session_scheduler.go`

## 2. 模块级改动矩阵（文件 -> 函数/入口 -> 改动点）

### 2.1 `backend/models/session_mode.go`

- **新增**：`NormalizeLegacySessionMode(s, m)`
  - 统一处理历史空 `session_mode` 的回退推断（回退到 `ResolveSessionMode(m)`）。
- **新增**：`ValidateSessionModeForEntry(s, m)`
  - Handler 入口模式守卫：
    - CS 入口期望 `cs`；Queue 入口期望 `qs/qm/qms/qmm`；
    - 历史空 mode 放行（避免历史数据误拦）。
- **新增**：`IsModeConsistentWithStatus(s)`
  - Scheduler 使用：检查 `session_mode` 与 `status` 前缀一致性。

### 2.2 `backend/handlers/service_session.go`

- **入口守卫新增**：
  - `handleServiceSessionStartScan`：加载会话后，状态推进前调用 `ValidateSessionModeForEntry(&s, &merchant)`。
  - `handleQueueModeStartScan`：加载会话后，状态推进前调用 `ValidateSessionModeForEntry(&s, merchant)`。
  - `ChooseServiceSessionRoom`：加载商户后，推进前调用 `ValidateSessionModeForEntry(&s, &m)`。
  - `ChooseServiceSessionTechnician`：加载商户后，推进前调用 `ValidateSessionModeForEntry(&s, &m)`。
- **legacy 兼容收敛**：
  - `handleQueueModeStartScan` 内 `qs` 单窗口判断由内联空 mode 逻辑改为：
    - `models.NormalizeLegacySessionMode(&s, merchant) == models.SessionModeQueueAutoSingle`

### 2.3 `backend/handlers/service_session_user.go`

- **入口守卫新增**：
  - `UserChooseServiceSessionRoom`：`ValidateSessionModeForEntry(&s, &merchant)`
  - `UserChooseServiceSessionTechnician`：`ValidateSessionModeForEntry(&s, &merchant)`
- **修复裸状态写入**：
  - `UserChooseServiceSessionRoom`：`"delay_pending"` 改为 `models.ApplyStatusPrefix(s.Status, "delay_pending")`

### 2.4 `backend/handlers/queue_status.go`

- **入口守卫新增**：
  - `TriggerContinueCalling`：锁定当前服务会话后，新增 `ValidateSessionModeForEntry(&s, &merchant)`。
  - `TriggerContinueCallingForce`：同上。
  - `TriggerNextCallingOnFinish`（/queue/finish-call-next）：触发叫号前增加“当前进行中会话模式一致性校验”（若无进行中会话则保持原行为，仅触发叫号）。

- **内部推进函数守卫新增（防未来绕过）**：
  - `assignNextSessionToTechnicianManual`：
    - 对取到的 `nextSession` / `anySession` 在推进前调用 `ValidateSessionModeForEntry`。
  - `promoteManualSingleCalledSession`：
    - 对锁定的 `ServiceSession` 在推进前调用 `ValidateSessionModeForEntry`。

- **错误码回退修复**：
  - `TriggerContinueCalling` / `TriggerContinueCallingForce`：在事务返回后补齐 `apiErr` 解包分支，避免业务守卫错误被当作 500 返回。

### 2.5 `backend/handlers/technician_attendance.go`

- **自动分配前置守卫**：
  - `tryAutoCallNextForTechnician`：加载 `nextSession` 后、更新前调用 `ValidateSessionModeForEntry(&nextSession, &merchant)`，不通过则 `Uncall` 并跳过。

### 2.6 `backend/scheduler/service_session_scheduler.go`

- **主分支前置守卫**：
  - `advanceOne`：在任何可能写库推进逻辑之前调用 `IsModeConsistentWithStatus(&s)`，不一致则打关键日志并跳过。

- **legacy 兼容收敛**：
  - `handleTimeoutWaiting`：`qs` 单窗口判定改为 `NormalizeLegacySessionMode(s, &merchant)`。
  - `skipCurrentAndCallNext`：同上。

## 4. legacy 空 mode 兼容收敛矩阵

| 场景 | 原写法 | 新写法 | 状态 |
|---|---|---|---|
| handler 内 qs 单窗口判断 | `s.SessionMode=="" && merchant...` | `NormalizeLegacySessionMode(&s, merchant)` | 已收敛 |
| scheduler timeout_waiting | `s.SessionMode != qs` | `NormalizeLegacySessionMode(s, &merchant)` | 已收敛 |
| scheduler skipCurrentAndCallNext | `s.SessionMode=="" && merchant...` | `NormalizeLegacySessionMode(s, merchant)` | 已收敛 |

## 5. 风险点与处置结果

- **风险点：queue_status 守卫错误被返回为 500**
  - **处置**：补齐 `apiErr` 解包，确保守卫失败返回 400。
- **风险点：scheduler 守卫不够前置**
  - **处置**：将 `IsModeConsistentWithStatus` 前移至任何推进逻辑之前。
- **风险点：queue_status 仍可能通过内部推进函数绕过守卫**
  - **处置**：在 `assignNextSessionToTechnicianManual` / `promoteManualSingleCalledSession` 内加入模式守卫。

## 6. 验收结论

- **P1（模式防串用校验）**：关键入口与关键推进链路已补齐守卫；legacy 空 mode 兼容逻辑已收敛到统一函数；scheduler 具备前置防串推进。
- **编译验证**：`backend` 目录下 `go build ./...` 通过。
