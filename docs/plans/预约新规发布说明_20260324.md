## 1. 发布概述

本次发布完成预约新规重构全链路落地，覆盖：

- 预约资源锁定
- 三阶段改签
- 商户取消与取消申请分流
- 预约结算与责任归属
- 不可抗力救济
- 拖堂账本与补偿兑现
- 请假异常修复与保护修复槽
- 月度免责与责任账本
- 系统优化性改签推荐（默认关闭）

## 2. 用户侧变化

- 用户预约详情新增：
  - 锁定时段
  - 取消截止时间
  - 商户取消原因
  - 用户抗辩意见
  - 结算与补偿结果
  - 拖堂账本
  - 不可抗力申请状态
- 用户主动改签升级为三阶段规则：
  - 阶段 A：可见更优于当前和不劣于当前
  - 阶段 B/C：仅可见更优于当前
- 用户可处理商户取消申请：
  - 同意取消
  - 拒绝取消
- 当商户开启推荐开关后，用户可看到系统优化性改签推荐卡片

## 3. 商户侧变化

- 商户预约详情新增：
  - 结算详情
  - 责任归属
  - 用户抗辩
  - 月度异常统计入口
  - 异常修复详情入口
  - `balanced / D-1 16:00 / D-1 18:00` 规则说明
- 商户取消逻辑升级：
  - `5` 小时前可直接取消
  - `5` 小时内只能发起取消申请
- 商户可发起保护性改签提议
- 商户预约设置新增：
  - 系统优化性改签推荐开关

## 4. 后端核心变化

- 预约模型补齐锁定、结算、责任与抗辩相关字段
- 新增预约结算快照与补偿收敛逻辑
- 新增不可抗力撤销申请承载层
- 新增客服月度异常计数与责任账本
- 新增预约拖堂账本与兑现逻辑
- 新增请假影响扫描与 `protected_repair_slots`
- 新增接口：
  - `GET /user/appointments/:id/reschedule-recommendations`
  - `GET /merchant/appointments/:id/repair-overview`

## 5. 发布注意事项

- 需先执行数据库迁移：
  - `cd backend && go run ./cmd/migrate`
- `系统优化性改签推荐` 默认关闭，不会主动影响现网预约主链
- 若上线后需灰度推荐能力，应先在商户端“预约设置”中手动开启
- 请假异常修复详情依赖：
  - 已发布排班
  - 已确认请假
  - 受影响预约扫描

## 6. 回归结果

- `cd frontend && npm run build:user`
- `cd frontend && npm run build:merchant`
