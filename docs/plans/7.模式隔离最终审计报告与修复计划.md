### Phase 4：过号插队窗口修复（P1）

修复 E1 — 用户已确认窗口为3个号

| # | 文件 | 行号 | 修复方式 |
|---|------|------|----------|
| 4a | `models/session_mode.go` | L50 | `myNo + 2 + 2*(cnt-1)` → `myNo + 3 + 2*(cnt-1)` |

**验证**：
- 单次过号 myNo=10, cnt=1: endNo = 10+3 = **13**, expired = currentNo >= 14 → 到14失败 ✅
- 连续过号 myNo=10, cnt=2: endNo = 10+3+2 = **15**, expired = currentNo >= 16

⚠️ **注意**：连续过号用例，设计文档说"到15失败"，修复后变为"到16失败"。这是因为原公式 `+2` 在 cnt=2 时恰好与设计文档一致，但 cnt=1 时少1个号。改为 `+3` 后 cnt=2 时会多1个号。

**两种方案**：
- **方案 A**（推荐）：公式改为 `myNo + 3 + 2*(cnt-1)`，同时更新设计文档连续过号用例为"到16失败"
- **方案 B**：公式改为 `myNo + 2 + 2*cnt`，即 cnt=1→endNo=12+2=14（到15失败❌），不符合

让我重新推导：
- 设计文档单次：myNo=10, 窗口3个号(11,12,13), 到14失败 → endNo=13, expired=currentNo>=14
- 设计文档连续(cnt=2)：10,11都过号, 到15失败 → endNo=14, expired=currentNo>=15

公式需满足：
- cnt=1: endNo = myNo + 3 = 13 ✅
- cnt=2: endNo = myNo + 3 + ? = 14 → 增量 = 1

所以连续过号每次增加1个号，不是2个号。正确公式：`myNo + 3 + (cnt-1)`

验证：
- cnt=1: 10 + 3 + 0 = **13**, expired = currentNo >= 14 → 到14失败 ✅
- cnt=2: 10 + 3 + 1 = **14**, expired = currentNo >= 15 → 到15失败 ✅

**最终修复**：`myNo + 2 + 2*(cnt-1)` → `myNo + 3 + (cnt-1)`

**共 1 处修改，预计 ~2 分钟**
