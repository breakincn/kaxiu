# E1与P1复核及修复实施方案

本方案先确认 E1 已否按“固定 3 个窗口”生效，再对全项目进行 P1（模式防串用校验）缺口审计，并给出可落地、分阶段的修复实施路径。

## 1. 结论摘要

- **E1（P0）当前已修复为固定 3 个窗口**。
  - `QsTimeoutWindowEndNo` 已固定返回 `myNo + 3`，`timeoutCount` 已不参与窗口放大。
  - 关键调用链（handler + scheduler）均通过 `QsTimeoutWaitingExpired` 走该固定窗口逻辑。
- **P1（模式防串用校验）仍存在缺口，问题仍成立**。
  - 当前是“按商户配置分支 + 局部 mode 判断”，**缺少统一、强约束的 session_mode 入口守卫**。
  - 多个状态推进写入点允许“仅凭当前 status/baseStatus 推进”，未显式校验 `session_mode` 与目标流程一致。

## 2. E1 复核证据

1) 固定窗口函数：
- `backend/models/session_mode.go`
  - `QsTimeoutWindowEndNo(myNo, timeoutCount)`：`return myNo + 3`
  - `QsTimeoutWaitingExpired` 调用该函数计算过号失效边界。

2) 调用链覆盖：
- `backend/handlers/service_session.go`
  - `handleQueueModeStartScan` 在 `timeout_waiting` 场景调用 `QsTimeoutWaitingExpired(currentNo, myNo, cnt)`。
- `backend/scheduler/service_session_scheduler.go`
  - `timeout_waiting` 自动推进逻辑同样调用 `QsTimeoutWaitingExpired(currentNo, myNo, cnt)`。

3) 额外说明：
- 手动叫号路径中还存在独立判定 `endNo := myNo + 3`，与固定窗口目标一致，不存在“按 timeoutCount 放大窗口”的旧实现。

## 3. P1 完整审计结果（仍有缺口）

### 3.1 当前已有防护（已做）

- 会话创建时写入 `session_mode` + 状态前缀（`WithModePrefix`/`WithCSPrefix`）。
- 大量状态读写已使用 `Normalize/Apply/Expand`，裸状态问题基本收敛。
- 部分局部防串：例如 `handleQueueModeStartScan` 对 `qs` 单窗口做了 `s.SessionMode == qs`（含历史空值兼容）判断。

### 3.2 仍存在的核心缺口（P1）

**缺口A：缺少统一入口守卫（session_mode 一致性校验）**
- 入口函数多以“商户当前配置”决定分支（CS/Queue），但对“已存在 session 的 `session_mode` 是否匹配当前入口语义”缺少统一硬校验。
- 结果：当商户配置切换、历史脏数据、跨接口调用混入时，可能出现“错误流程入口推进了不匹配模式会话”。

**缺口B：状态推进点普遍未绑定模式约束**
- 多个 `Updates(status=ApplyStatusPrefix(...))` 仅依赖当前 status/业务前置条件，未先校验该 session 是否允许在当前模式推进。
- 典型分布：
  - `handlers/service_session.go`（起单、选房、选人、扫码上号）
  - `handlers/service_session_user.go`（用户端选房/选人）
  - `handlers/queue_status.go`（继续叫号、跳过、分配下一号）
  - `handlers/technician_attendance.go`（签到后自动分配）
  - `scheduler/service_session_scheduler.go`（timeout_waiting、skip/finalize 等自动推进）

**缺口C：历史空 mode 的兼容散落在业务点，缺少集中策略**
- 目前在个别点通过 `s.SessionMode == "" && merchant...` 兜底，规则分散，未来易出现分支不一致。

## 4. 修复实施方案（分阶段）

### Phase 1（P1-最高优先，先收敛单点）

1) 新增统一模式守卫工具（建议放 `backend/models/session_mode.go` 或同 package 新文件）
- 建议函数：
  - `ExpectedSessionModeByMerchant(m *Merchant) string`
  - `IsQueueMode(mode string) bool`
  - `ValidateSessionModeForEntry(s *ServiceSession, m *Merchant, entry string) error`
  - `NormalizeLegacySessionMode(s *ServiceSession, m *Merchant) string`（仅返回，不直接写库）
- 规则目标：
  - CS 入口仅允许 `cs`（必要时兼容空 mode 且可推导）；
  - Queue 入口仅允许 `qs/qm/qms/qmm`（必要时兼容空 mode）；
  - 非 queue 入口拒绝 queue mode 会话，反之亦然。

2) 在所有“会话状态推进入口”先执行守卫，再推进状态
- 必改入口：
  - `handleServiceSessionStartScan` / `handleQueueModeStartScan`
  - `ChooseServiceSessionRoom` / `ChooseServiceSessionTechnician`
  - `UserChooseServiceSessionRoom` / `UserChooseServiceSessionTechnician`
  - `queue_status` 的继续叫号/强制继续/结单触发下一号
  - `technician_attendance` 自动分配路径
  - scheduler 的 `advanceOne` 分支入口

3) 守卫失败的返回策略统一
- HTTP 入口：`400` + 明确文案（例如“会话模式与当前流程不匹配，请刷新后重试”）。
- scheduler：记录关键告警日志并跳过该会话（避免错误推进）。

### Phase 2（P1-高优先，减少散落兼容）

4) 增加“集中兼容策略”
- 将 `session_mode == ""` 的历史兼容判断统一放在 `NormalizeLegacySessionMode`，业务代码不再手写条件。
- 逐步在关键入口落库回填（可选）：当能确定 mode 时，一次性补写 `session_mode`。

5) 增加配置切换期间的会话防护
- 在商户开关变更（queue_mode / support_multi_customer_service / customer_service_mode）路径上，除现有“有进行中会话禁止切换”外，增加对 `session_mode` 异常会话计数告警，避免切换后产生混推。

### Phase 3（质量保障）

6) 回归测试与用例补齐
- 单测：
  - `ValidateSessionModeForEntry` 覆盖 cs/qs/qm/qms/qmm + legacy 空 mode。
  - `QsTimeoutWindowEndNo` 固定 3 窗口边界值。
- 集成测试：
  - 配置切换前后，旧 session 通过错误入口请求时被拒绝；
  - scheduler 不会把 mode 不匹配会话推进到错误状态；
  - queue 手动/自动、单/多窗口四种模式全覆盖。

## 5. 变更清单建议（按文件）

- `backend/models/session_mode.go`
  - 增加统一模式校验与 legacy 兼容函数。
- `backend/handlers/service_session.go`
  - 在扫码起单、选房、选人主入口增加守卫。
- `backend/handlers/service_session_user.go`
  - 用户端选房/选人入口增加守卫。
- `backend/handlers/queue_status.go`
  - 继续叫号/强制继续/finish-call-next 等推进入口增加守卫。
- `backend/handlers/technician_attendance.go`
  - 自动分配前增加守卫。
- `backend/scheduler/service_session_scheduler.go`
  - `advanceOne` 分支最前置增加守卫，异常跳过并打关键日志。

## 6. 验收标准

- E1：任意 `timeoutCount` 下，窗口上界恒为 `myNo + 3`。
- P1：所有状态推进点在执行前均经过 `session_mode` 守卫。
- 不再存在“仅依赖商户配置分支、未校验 session_mode 就推进状态”的入口。
- 历史空 `session_mode` 兼容逻辑只保留在统一函数，不再散落业务代码。
