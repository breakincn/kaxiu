# 预约功能闭环重构计划完成对照清单

日期：2026-03-17

## 已完成

### 后端模型与迁移
- 已新增商户预约保护参数字段并补迁移。
- 已新增 `appointments` 的确认、到店、完成、失约、会话绑定、备注等字段。
- 已新增 `service_sessions` 的压预约风险标记与预计可服务时间字段。

### 预约状态机
- 已把预约主状态调整为 `pending / confirmed / arrived / completed / canceled / failed / no_show`。
- 已统一兼容历史 `finished -> completed` 的读取语义。
- 已废弃独立“完成预约”入口，改为随核销/服务会话闭环。

### 预约保护策略
- 已实现预约占产能。
- 已实现统一候选客服规则。
- 已实现 `safe / conditional / unavailable`。
- 已实现客服模式下“预约保护 + 替代优先”决策。
- 已在压预约派单时写入风险标记。

### 到店核销闭环
- 已在核销提交阶段把命中预约的状态推进为 `arrived`。
- 已回写 `usage_id` 与 `service_session_id`。
- 已把预约来源会话纳入正式 `ServiceSession` 流转。
- 已在原客服忙碌时进入 `appointment_waiting`。

### 调度器
- 已新增 `appointment_waiting` 的推进逻辑。
- 已保证客服释放后优先推进预约等待项。
- 已新增 `confirmed -> no_show` 的自动推进。
- 已保留未选客服预约的自动分配，并切换到预约保护规则。

### 服务完成回写
- 已在预约来源会话完成时把预约同步标记为 `completed`。
- 已覆盖“未正式起单但被系统收尾完成”的预约来源会话。

### 商户端
- 已支持商户账号直接进入预约页。
- 已移除旧的“完成服务(扣次)”按钮依赖。
- 已增加新状态展示：
  - `arrived`
  - `completed`
  - `failed`
  - `no_show`
- 已增加预约风险提示。
- 已增加处理备注展示。
- 已提供三类冲突处理入口：
  - 继续等待原客服
  - 改派其他客服
  - 改签/补偿备注

### 用户端
- 已在预约页展示客服候选的可用性状态。
- 已对风险可约客服展示预计等待分钟数。
- 已在预约详情返回 `service_session_id`、`predicted_wait_minutes`、`can_arrive_now`。

### 商户配置页
- 已增加四个预约保护参数的配置输入。

### 测试与验证
- 已新增测试：
  - 预约超时进入 `no_show`
  - 预约来源会话完成后同步预约 `completed`
- 已通过：
  - `go test ./handlers ./scheduler ./sessionflow`
  - `go test ./...`
  - `npm run build:merchant`
  - `npm run build:user`

## 保留兼容
- `PUT /merchant/appointments/:id/finish` 仍保留路由，但仅返回废弃提示。
- 历史 `finished` 状态仍能兼容读取为 `completed`。
- 当前预约优先等待仍复用 `ServiceSession`，没有单独引入新的持久化排队表。

## 下一步待完成

### 业务能力补强
- 预约改签已实现正式工作流：商户端可选择新时间并提交，系统会关闭原预约、生成新预约并建立替代关系。详细对照见 [改签及补偿计划方案与实施对照清单.md](/Users/will/Projects/Go/kabao/docs/plans/改签及补偿计划方案与实施对照清单.md)。
- 补偿已实现正式入口与记录流转：支持补次数、补时长、优惠减免记录、其他补偿记录；其中财务/营销系统联动仍待后续补齐。
- 预约等待中的“改派其他客服”当前先基于空闲客服列表与手工选择，尚未做到严格的“同技能自动筛选 + 可视化选择弹窗”。

### 规则深化
- 当前 `appointment_waiting` 已保证优先级，但还没有单独的用户通知与到店提醒文案链路。
- 预约自动分配与到店等待的解释性文案还可以继续细化，例如统一在商户端展示成本比较原因。
- `no_show` 已自动推进，但还没有补用户端的失约提醒与后续改签建议。

### 持久化与运营能力
- 尚未引入独立 `queue_tickets` 或更通用的预约/现场统一队列表。
- 继续等待原客服目前不需要后端写状态，只做刷新与优先等待承诺，后续可考虑补显式操作日志。
- 处理备注目前只有更新接口，没有独立操作历史表。

### 体验优化
- 商户端“改派其他客服”目前使用简单输入式交互，后续建议改成可视化弹层。
- 用户端预约详情还可以继续增加“已到店等待原客服 / 已开始服务”的细粒度文案。
