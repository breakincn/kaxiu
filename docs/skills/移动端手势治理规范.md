# 移动端手势治理规范
**时间**：2026-04-06
**执行者**：Codex

## 文档目标

本文档在 `mobile-tap-gesture-guard` skill 的基础上，进一步沉淀为当前项目可执行的移动端手势治理规范，用于统一处理以下冲突：

- 轻点进入详情
- 长按打开菜单或二维码
- 纵向滚动浏览页面
- 列表项内嵌通知区、CTA、badge 等次级热区

## 治理目标

项目内所有移动端热区，优先满足以下结果：

1. 用户轻点时，行为只触发一次。
2. 用户上下滑动时，不得误触发点击或跳转。
3. 长按成立后，不得再回落到详情跳转。
4. 嵌套热区不能因为 `touchend` 直接导航而成为误触源。
5. 桌面端鼠标点击行为保持可用。

## 页面模式分级

为避免每次零散判断，建议把项目页面按三类管理：

### A. 已对齐

定义：

- 已采用受控 tap
- `touchstart` 立即记录起点
- `touchmove` 超阈值取消长按并屏蔽 click
- `touchend` 仅在未滑动且未长按时执行主行为
- 嵌套热区也独立做 guard

当前样例：

- [frontend/src/views/user/CardList.vue](/Users/will/Projects/Go/kabao/frontend/src/views/user/CardList.vue)

### B. 部分对齐

定义：

- 已存在长按定时器
- 已存在位移阈值
- 但轻点/桌面点击/嵌套热区规则还不够统一

当前样例：

- [frontend/src/views/user/CardDetail.vue](/Users/will/Projects/Go/kabao/frontend/src/views/user/CardDetail.vue)

现状判断：

- 优点：起点记录及时，移动后会取消长按
- 后续方向：如果该列表未来也有轻点直达行为，建议统一到同一套 guarded tap 方案

### C. 旧混合模式

定义：

- 仍然主要依赖 `click`
- `touch` 只用于长按或局部抑制
- 起点记录和 suppress 逻辑未完全闭环

当前样例：

- [frontend/src/views/merchant/Dashboard.vue](/Users/will/Projects/Go/kabao/frontend/src/views/merchant/Dashboard.vue)

现状判断：

- 该页顶部扫码入口仍是“`click` 决定主行为 + 长按补充行为”的旧模式
- 若后续出现误触反馈，应优先迁移为受控 tap

## 统一实现原则

### 1. 主热区统一事件签名

推荐主热区统一为：

```vue
@click="onItemClick($event, id)"
@touchstart="onItemTouchStart($event, item)"
@touchmove="onItemTouchMove"
@touchend="onItemTouchEnd($event, item)"
@touchcancel="onItemTouchCancel"
```

### 2. 主热区统一状态

建议最小状态集：

- `startX/startY`
- `moved`
- `longPressed`
- `activeItemId`
- `suppressClickUntil`
- `longPressTimer`

### 3. 嵌套热区独立状态

不要把通知区、CTA、badge 的行为混在父容器状态里“顺便处理”。

嵌套热区应自己维护：

- 起点
- 位移判断
- `touchend` 条件触发
- `click` 抑制

### 4. CSS 只做辅助，不做主判定

推荐加：

```css
touch-action: pan-y;
```

但不允许只靠这条样式解决误触问题。

## 推荐参数

统一建议如下：

- 位移阈值：`8px`
- 滚动取消后 click 抑制：`350ms`
- 正常轻点打开后 click 抑制：`500ms`
- 长按触发时长：`820ms`
- 长按后 click 抑制：`900ms`

## 改造优先级

后续如要继续治理，建议顺序如下：

1. 用户侧、会误入详情的页面优先
2. 含嵌套热区的列表页优先
3. 商户工具类页面其次

## 验收要求

任何页面完成治理后，至少验证：

1. 轻点一次，仅执行一次。
2. 快速上下滑动，不误触发。
3. 慢速拖动超过阈值，不误触发。
4. 长按只触发长按行为。
5. 嵌套热区轻点可用、滑动不误触。
6. 长按或滑动结束后，不因浏览器补发 `click` 出现二次触发。
7. 桌面端鼠标点击仍可工作。

## 对接 skill 的方式

处理这类任务时，优先直接引用 skill：

- `用 $mobile-tap-gesture-guard 修这个移动端列表误触问题`
- `按 $mobile-tap-gesture-guard 的治理规范统一这个页面手势`

若需求明显属于移动端滚动误触，也应默认按该 skill 处理，而不是重新发明一套触摸逻辑。

## 结论

当前项目已经具备一套可落地、可复用、可扩展的移动端手势治理基线。后续新增或改造移动端可点击列表页时，应默认把 `mobile-tap-gesture-guard` 视为标准技能，把本规范视为项目级执行准则。
