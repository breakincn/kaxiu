## 适用场景

当页面满足以下一种或多种情况时，应优先使用该 skill：

- 列表项、卡片项支持轻点进入详情
- 同一块区域还支持长按弹出菜单、操作面板或二维码
- 列表项内部存在通知区、按钮区、badge 等嵌套热区
- 用户在移动端上下滑动页面时，容易误触发 `click` 或页面跳转
- `touchend` 后浏览器补发 `click`，导致一次手势触发两次行为

典型例子：

- 用户卡片页上下滑动时误入卡片详情
- 卡片内部置顶通知在滚动过程中误跳详情
- 长按打开 action sheet 后，松手又触发一次点击跳转

## 核心设计原则

### 1. 不让原生 click 决定移动端触摸意图

移动端可点击列表项不要采用“`touch` 负责长按，`click` 负责进入详情”的松散组合。

应采用受控 tap 流程：

1. `touchstart` 记录起点坐标与当前项 id
2. `touchmove` 超过阈值后，立刻认定为滑动
3. `touchend` 只有在“未滑动、未长按”时才执行详情跳转
4. `click` 仅保留给桌面端兜底，并通过抑制窗口吞掉触摸后的合成 click

### 2. 长按逻辑只负责长按

长按一旦成立：

- 必须设置 `longPressed = true`
- 必须清除按压视觉态
- 必须屏蔽后续 click
- 必须只打开长按菜单，而不能再落入详情跳转

### 3. 嵌套热区也必须独立做 tap guard

卡片里的通知区、CTA、按钮区，不能直接写：

```vue
@touchend="goToDetail()"
```

因为这会让用户从该区域起手滚动时仍被误判为点击。

嵌套热区必须拥有自己独立的：

- 起点记录
- 位移阈值判断
- `touchend` 条件执行
- `click` 抑制逻辑

## 推荐参数

建议默认参数如下：

- 滑动阈值：`8px`
- 滚动取消后的 click 抑制时间：`350ms`
- 轻点打开详情后的 click 抑制时间：`500ms`
- 长按触发时长：`820ms`
- 长按后的 click 抑制时间：`900ms`

CSS 辅助建议：

```css
.your-card-class {
  touch-action: pan-y;
}
```

注意：`touch-action: pan-y` 只是浏览器提示，不是主修复手段。真正决定是否跳转的仍然是 `touchmove` 阈值与 `touchend` 条件判断。

## 推荐接入方式

对于主列表项，建议使用以下事件签名：

```vue
@click="onItemClick($event, id)"
@touchstart="onItemTouchStart($event, item)"
@touchmove="onItemTouchMove"
@touchend="onItemTouchEnd($event, item)"
@touchcancel="onItemTouchCancel"
```

页面内建议维护以下本地状态：

- `startX/startY`
- `moved`
- `longPressed`
- `activeItemId`
- `suppressClickUntil`
- `longPressTimer`

不建议一开始就抽成公共 composable。只有当多个页面出现完全一致的交互模式时，再考虑抽象。

## 使用方式

后续提需求时，可以直接在任务里显式提这个 skill，例如：

- `用 $mobile-tap-gesture-guard 修这个移动端列表误触问题`
- `按 $mobile-tap-gesture-guard 的模式，把这个卡片列表改成可滚动不误触`
- `参考 $mobile-tap-gesture-guard，处理长按和轻点冲突`

如果不显式提 skill，但需求明显属于“移动端滑动误触点击/导航冲突”，也应优先按该 skill 的规则实施。

## 验证清单

每次使用该 skill 修复页面后，至少验证以下场景：

1. 轻点一次，只触发一次目标行为。
2. 快速上下滑动，不触发目标行为。
3. 慢速拖动超过阈值，不触发目标行为。
4. 长按只打开菜单，不再触发详情跳转。
5. 嵌套热区轻点正常，滑动经过不误触。
6. 桌面端鼠标点击仍可正常工作。
7. 一次长按或一次滑动结束后，不会因为浏览器补发 `click` 导致二次触发。

## 不应采用的写法

- 在移动端热区直接用原始 `@touchend="navigate()"`
- `touchstart` 不记录起点，而在第一次 `touchmove` 才记录
- 只靠 `click.prevent` 解决误触
- 明明还没形成复用规模，就过早抽象成全局公共层

## 结论

`mobile-tap-gesture-guard` 已适合沉淀为当前项目处理“移动端滚动误触点击/导航”问题的标准技能。后续凡是出现“轻点、长按、滑动、嵌套热区”四者并存的页面，都应优先复用该技能，而不是重新各写一套触摸判断。
