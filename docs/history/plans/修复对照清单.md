## Phase 1（P1）：修复 F1（手动叫号 timeout_waiting 超限扫码失败缺少 MarkDone）

### 对应缺陷
- **F1（P1）** 手动叫号 `timeout_waiting` 扫码失效分支缺少 `queue.MarkDone`，可能阻塞后续叫号。

### 修复点（已实施）
- **文件**：`backend/handlers/service_session.go`
- **位置**：`handleQueueModeStartScan` 中 `baseStatus == "timeout_waiting"` 且 `merchant.QueueMode == "manual"` 的“超限失败”分支。
- **改动**：在会话写入 `timeout_failed` 之后、usage 置 `failed` 之前补充：
  - `queue.Default.MarkDone(merchant.ID, date, queue.QueueTypeOnsite, s.InitialUsageID, now)`

### 预期效果
- 手动叫号（`qms/qmm`）在 `timeout_waiting` 且超限扫码时：
  - session：进入 `timeout_failed`
  - usage：进入 `failed`
  - 卡次：回滚
  - 队列：该号被 `done` 标记，`CallNextUncalled` 不再反复命中该号

### 验证方式
- **回归测试**：依赖 Phase 2 的 scheduler 幂等兜底测试与人工回归（见 Phase 2 / 手动回归项）。
- **人工回归**：
  - 商户配置 `support_queue=true`、`queue_mode=manual`，创建一个会话进入 `timeout_waiting`
  - 模拟超号段且超时间窗口后扫码
  - 观察 Redis 队列 `done` 中对应 `initial_usage_id` 已写入（并且下一号可推进）

## Phase 2（P2）：修复 F2（timeout_failed 缺少调度幂等收尾兜底）

### 对应缺陷
- **F2（P2）** `timeout_failed` 无调度分支，缺少后续幂等收尾兜底。

### 修复点（已实施）
- **文件**：`backend/scheduler/service_session_scheduler.go`
- **改动 1**：在 `advanceOne` 的 `switch baseStatus` 中增加：
  - `case "timeout_failed": return handleTimeoutFailed(tx, &s, now)`
- **改动 2**：新增函数 `handleTimeoutFailed`，幂等兜底：
  - 若商户开启叫号且 `queue.Default != nil`：补 `queue.MarkDone(...)`
  - 若 usage 仍是 `in_progress`：补写 `failed` + `finished_at`
  - 若 usage 仍是 `in_progress`：补退卡次（`cards.remain_times + used_times`、`cards.used_times - used_times`）

### 回归用例（已新增自动化测试）
- **文件**：`backend/scheduler/service_session_scheduler_test.go`
- **用例**：`TestAdvanceOne_TimeoutFailed_DoesIdempotentCleanup`
  - 断言：
    - `MarkDone` 被调用
    - usage 从 `in_progress` -> `failed`，且 `finished_at` 被写入
    - 卡次回滚
    - 重复跑 scheduler 不会重复退卡（幂等）

### 额外：测试环境稳定性修复
- **文件**：`backend/scheduler/service_session_scheduler_test.go`
- **改动**：sqlite DSN 增加 `_time_format=2006-01-02 15:04:05.999`，并避免在不需要时设置 `FinishedAt`，防止 sqlite 时间字段扫描报错。

### F4：看板倒计时优先使用会话级 start_pending_timeout_seconds

#### 对应缺陷
- **F4（P3）** 看板倒计时未使用会话级 `start_pending_timeout_seconds`。

#### 修复点（已实施）
- **文件**：`backend/handlers/table.go`
- **位置**：
  - `TableRooms`：`start_pending` 倒计时计算
  - `TableStaff`：`start_pending` 倒计时计算
- **改动**：
  - `timeout := config.StartPendingTimeout()`
  - `if s.StartPendingTimeoutSeconds > 0 { timeout = time.Duration(s.StartPendingTimeoutSeconds) * time.Second }`
  - `startDeadline := s.UpdatedAt.Add(timeout)`

#### 验证方式
- 创建会话 `StartPendingTimeoutSeconds` 设置为非 0（秒）
- 看板接口返回的 `start_remain_seconds` 与该会话配置一致（而不是全局默认值）
