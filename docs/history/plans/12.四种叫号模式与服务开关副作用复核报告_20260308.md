## 一、结论总览

### 1.1 总体结论

当前代码中，四种叫号模式 `qs / qm / qms / qmm` 的主链路整体是闭环的：

- 核销创建 `Usage + ServiceSession`
- 现场叫号入队
- 自动/手动推进到 `start_pending` 或 `delay_pending`
- 扫码上号进入 `serving`
- 服务完成/超时后回写 `usage/card/queue`
- 自动或人工继续触发下一号

`session_mode`、状态前缀和入口守卫已经覆盖了大部分“跨模式串台”风险，调度器也加入了 `mode/status` 一致性检查，四种模式的正常链路基本可用。

### 1.2 关键审计结论

- `qs` 自动单窗口：主链路完整，过号插队窗口闭环，队列推进与超时退卡逻辑一致。
- `qm` 自动多窗口：主链路完整，依赖空闲技师分配、`start_pending` 超时降级与释放技师后自动补叫，链路闭环。
- `qms` 手动单窗口：主链路完整，`call-next / continue-call / finish-call-next / timeout_waiting` 回补逻辑可运行。
- `qmm` 手动多窗口：主链路完整，技师维度分配、继续叫号、强制继续、结单触发下一号均已串起。

### 1.3 本次确认的主要风险

当前最明显的副作用风险不在四种模式自身，而在**商户服务开关运行中切换**：

1. **高优先级 P1**：运行中可直接关闭 `support_queue`，当前没有“有进行中叫号会话时禁止关闭”的保护。  
2. **高优先级 P1**：运行中可以通过“同一请求里关闭 `support_queue` + 开启 `support_customer_service_mode`”绕过现有保护，把仍在运行的叫号会话暴露给客服模式调度逻辑。  

这两个问题都不是“链路缺失”，而是“运行中切配置会改变会话推进语义”，会产生真实副作用。

## 三、服务开关副作用矩阵

## 3.1 客服模式 `support_customer_service_mode`

正向保护：

- 与 `support_queue` 互斥，不能同时为 true。 [`backend/handlers/merchant.go:319`](/Users/will/Projects/Go/kabao/backend/handlers/merchant.go#L319)

副作用风险：

- 现有保护只拦“目标状态同时开启 queue + cs”，**没有拦“运行中把 queue 关掉，再把 cs 打开”**。
- 这样会让仍在运行的 queue 会话面对新的客服模式配置，后续 `ValidateSessionModeForEntry`、调度器推进和完成语义都会改变。

结论：**存在高风险切换窗口，见 P1-1。**

## 四、风险清单

## P1-1 运行中可关闭 queue 或切到客服模式，导致正在运行的叫号会话语义漂移

严重级别：高

触发条件：

- 商户存在活跃 queue 会话；
- 直接把 `support_queue` 改成 `false`，或者同一请求里 `support_queue=false` 且 `support_customer_service_mode=true`。

依据：

- 当前只保护 `queue_mode` 和 `support_multi_customer_service`，未保护 `support_queue` 自身。 [`backend/handlers/merchant.go:336`](/Users/will/Projects/Go/kabao/backend/handlers/merchant.go#L336)
- `timeout_waiting` 在 `support_queue=false` 时直接跳过，不再处理退款/终态。 [`backend/scheduler/service_session_scheduler.go:1336`](/Users/will/Projects/Go/kabao/backend/scheduler/service_session_scheduler.go#L1336)
- `finalizeSession` 在 `support_queue=false` 时不再 `MarkDone`，队列侧 done 状态可能遗留。 [`backend/scheduler/service_session_scheduler.go:1630`](/Users/will/Projects/Go/kabao/backend/scheduler/service_session_scheduler.go#L1630)
- `handleServing`、`handleRoomLockedOrStaffSelecting` 等推进逻辑会读取当前商户配置；若切到客服模式，旧 queue 会话会落入新的语义分支。 [`backend/scheduler/service_session_scheduler.go:1007`](/Users/will/Projects/Go/kabao/backend/scheduler/service_session_scheduler.go#L1007)

影响：

- queue 会话可能不再按 queue 逻辑完成回收；
- `usage/card/queue` 三者的一致性可能被破坏；
- 旧 queue 会话可能被客服模式逻辑继续推进，产生跨模式副作用。

建议：

- 把 `support_queue` 与 `support_customer_service_mode` 的运行中切换一起纳入“有活跃 queue 会话则禁止切换”的保护范围。
