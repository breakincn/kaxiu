### 2.1 模式防串用校验（P2）详细说明

设计文档要求"状态推进必须在所属模式状态机内进行"，当前代码中：
- **无** `session_mode` 与 `status` 前缀一致性校验
- **无** 入口级别的模式路由守卫（如 cs_ 会话不应走 qs_ 推进接口）
- `handleQueueModeStartScan` 仅通过 `isQueueMode`（商户配置）判断，未校验 `session.SessionMode`

建议实施方案：
1. 在 `handleServiceSessionStartScan` 中校验 `session.SessionMode` 与当前商户模式一致
2. 在 `handleQueueModeStartScan` 中校验 `session.SessionMode` 以 `qs`/`qm`/`qms`/`qmm` 开头
3. 在选房/选技师接口中校验 `session.SessionMode == "cs"` 系列

### 2.2 客服子模式扩展（P3）详细说明

当前 `ResolveSessionMode` 对所有客服模式统一返回 `"cs"`，未区分四种客服子模式：

| 子模式 | 条件 | 当前状态 |
|--------|------|----------|
| cs_无房间自动 | SupportCSMode && !SupportOrderComplete && !SupportRoom | ✅ 已实现 |
| cs_房间自动 | SupportCSMode && !SupportOrderComplete && SupportRoom | ✅ 已实现 |
| cs_手动结单 | SupportCSMode && SupportOrderComplete && !SupportRoom | ❌ 未实现 |
| cs_房间手动 | SupportCSMode && SupportOrderComplete && SupportRoom | ❌ 未实现 |

### 4.3 修复原则

所有修复遵循统一原则：
1. **状态写入**：使用 `models.ApplyStatusPrefix(s.Status, "newStatus")` 保持当前前缀
2. **状态比较**：使用 `models.NormalizeSessionStatus(s.Status) == "baseStatus"` 去前缀比较
3. **WHERE 条件**：使用 `models.ExpandStatusWithKnownPrefixes("baseStatus")` 或 `models.ExpandStatusesWithKnownPrefixes([]string{...})` 扩展为全前缀集合
4. **非 ServiceSession 表**：`Usage`、`TechnicianAttendance`、`Appointment` 的 status 不使用模式前缀，保持原样
